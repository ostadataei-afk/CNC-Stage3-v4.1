# نسخهٔ ماژولار CNC / OptiCut

این مخزن یک پردازشگر ماژولار PowerShell برای فایل‌های DXF خروجی OptiCut است. ورودی‌ها تحلیل می‌شوند و فایل‌های خروجی با شیار `SH` و بریدگی دستگیرهٔ `Z` ساخته می‌شوند.

## اجرای برنامه

از ریشهٔ پروژه، در PowerShell 7:

```powershell
./Invoke-Cnc.ps1 -ValidateOnly
./Invoke-Cnc.ps1 -SourceFolder ./tests/Sample_A_Valid -OutputFolder ./Output -ValidateOnly
./Invoke-Cnc.ps1 -SourceFolder ./tests/Sample_A_Valid -OutputFolder ./Output
```

می‌توانید `Run-Cnc.cmd` را هم اجرا کنید. این اجراکننده ابتدا PowerShell قابل‌حمل در پوشهٔ `PowerShell/7` را می‌جوید و در نبود آن، `pwsh` را از مسیر سیستم اجرا می‌کند. برای استفاده روی دستگاه دیگر، PowerShell 7 نصب کنید.

**هشدار:** اجرای عادی، پس از اعتبارسنجی و پیش از ذخیره، محتوای پوشهٔ خروجی را پاک می‌کند. پیش‌فرض ورودی `Desktop/A` و خروجی `Desktop/B` است. حالت `ValidateOnly` خروجی نهایی را ذخیره نمی‌کند؛ فایل‌های موقت برای بررسی دوبارهٔ DXF ایجاد و پاک می‌شوند. برای اجرا از پوشهٔ خروجی اختصاصی استفاده کنید.

## تقسیم مسئولیت‌ها

| فایل در `src` | مسئولیت |
|---|---|
| `Dxf.ps1` | خواندن DXF، کدهای گروه، متن‌ها، لایه‌ها و نوشتن موجودیت‌ها |
| `Rules.ps1` | دستور زبان SH/Z، اندازه‌ها، جدول‌ها و جهت عملیات |
| `Geometry.ps1` | مستطیل، حدود، رأس بریدگی و کنترل تداخل و ایمنی هندسه |
| `OptiCut.ps1` | تشخیص قالب Legacy/Layered، اتصال متن به قطعه و ساخت طرح اولیه |
| `Planning.ps1` | جفت‌سازی قطعات در چند فایل و تعیین نقش و جهت نهایی |
| `Generation.ps1` | اعمال طرح، تولید خطوط DXF و بررسی خروجی بازخوانی‌شده |
| `Pipeline.ps1` | رابط پردازش دسته‌ای در حافظه و قرارداد مستقل JSON |
| `Application.ps1` | مسیرها، پیام‌ها، اعتبارسنجی دسته‌ای، ذخیره و مدیریت فایل‌ها |

`Cnc.psm1` نقطهٔ بارگذاری ماژول است. اجزا در محدودهٔ داخلی همین ماژول بارگذاری می‌شوند و برای هر اجرا تابعی از متن برنامه استخراج نمی‌شود. وابستگی پنهان توابع به فرهنگ عددی و تلورانسِ فراخواننده حذف شده است؛ تلورانس‌های قبلی ۰٫۰۵ و ۰٫۱ میلی‌متر به‌صورت محلی حفظ شده‌اند.

## قالب برچسب عملیات

برچسب می‌تواند با یک نام یا توضیح دلخواه آغاز شود؛ این بخش با اولین `_` یا `-` تمام می‌شود. نام می‌تواند خالی باشد. پس از آن باید یک یا دو دستور `SH` و `Z` بیاید؛ ترتیب آن‌ها آزاد است. برای نمونه، `SH-Z`، `_Z-SH` و `-SH_Z` معتبرند و `Zir _ SH 100 _ Z` نیز نام `Zir` را همراه دو دستور تعریف می‌کند.

فاصله‌های پیرامون جداکننده‌ها و در دو سوی دستور و عدد نادیده گرفته می‌شوند؛ بنابراین `SH 25` معادل `SH25` و `300 SH 25` معادل `300SH25` است. عدد باید پس از حذف فاصله‌ها قالب عددی معتبر داشته باشد؛ فاصلهٔ داخل عدد مجاز نیست. دستور تکراری، توکن نامعتبر در بخش دستورات، جداکنندهٔ تکراری یا دستور سوم خطاست. متن عادی بدون دستور قابل‌شناسایی، مانند `WASH` یا `SHABC`، توضیح محسوب می‌شود و نامزد برچسب نیست.

## رابط پردازش در حافظه

```powershell
Import-Module ./Cnc.psm1 -DisableNameChecking
$documents = @(Get-ChildItem ./tests/Sample_A_Valid/*.dxf |
    Sort-Object Name | ForEach-Object { Read-DxfDocument $_ })
$plans = New-CncBatchPlan -Documents $documents
$contract = ConvertTo-CncPlanContract -Documents $plans
$outputs = ConvertTo-CncOutput -Documents $plans
```

ساخت طرح و تولید خطوط در حافظه انجام می‌شوند. خواندن ورودی و بررسی بازخوانی خروجی بر عهدهٔ بخش DXF است. رابط پیشنهادی برای مصرف جدید شامل `New-CncBatchPlan`، `ConvertTo-CncPlanContract`، `ConvertTo-CncOutput` و `Invoke-CncBatch` است.

**طرح‌ها تغییرپذیرند:** برنامه‌ریزی و تولید، اشیای ورودی را تغییر می‌دهند. برای اجرای دوباره، اسناد را از نو بخوانید. قرارداد JSON تصویر جداگانه‌ای از طرح است و به اشیای داخلی ارجاع ندارد؛ آن را پیش از تولید دریافت کنید.

## گسترش و مهاجرت به زبان دیگر

برای گرفتن طرح قابل‌مقایسه، بدون تولید فایل CNC:

```powershell
./Export-Plan.ps1 -SourceFolder ./tests/Sample_A_Valid > plan.json
```

پیام‌های تشخیصی این فرمان از خروجی JSON حذف می‌شوند. قرارداد نسخهٔ ۱ شامل واحد `mm`، نام و قالب فایل، شناسهٔ قطعه، برچسب، محدودهٔ هندسی، جدول، نقش و جهت، مشخصات شیار و بریدگی است. مقدار عملیات غایب `null` است و مجموعه‌های `files` و `operations` همیشه آرایه‌اند.

این JSON برای تبادل و مقایسهٔ تصمیم‌های CNC است؛ بازسازی کامل DXF از آن پشتیبانی نمی‌شود و برنامه نیز فعلاً آن را به‌عنوان ورودی نمی‌خواند. اطلاعات کامل موجودیت‌ها و سربرگ DXF در مدل داخلی باقی می‌مانند.

مراحل توسعهٔ پیشنهادی:

۱. تحلیل برچسب و جدول قواعد را توسعه دهید و آزمون‌های مثبت و منفی را معیار قرار دهید.
۲. هندسه را با همان واحد، تلورانس، گردکردن سه‌رقمی و ترتیب رأس‌ها نگه دارید.
۳. تشخیص OptiCut و جفت‌سازی بین فایل‌ها را با قرارداد JSON بررسی کنید.
۴. خواندن و نوشتن DXF را با فایل‌های مرجع بسنجید.
۵. رابط اجرا و مدیریت فایل‌ها را توسعه دهید.

این برنامه همچنان از اشیای PowerShell و ساختار تغییرپذیر استفاده می‌کند؛ تبدیل خودکار به زبان دیگر نیست. مرز فایل‌ها، رابط پردازش و JSON نقاط شروع مشخصی برای مهاجرت فراهم می‌کنند. بعضی توابع دامنه پیام تشخیصی `Write-Host` دارند؛ برای رابط کتابخانه‌ای زبان دیگر بهتر است این پیام‌ها به گزارش‌دهندهٔ جدا منتقل شوند.

## آزمون‌ها

```powershell
./tests/Run-Tests.ps1
```

آزمون‌های برچسب، هندسه، OptiCut و حفظ ورودی و خروجی همین پیاده‌سازی را بررسی می‌کنند. داده‌های آزمون داخل پوشهٔ `tests` هستند. هیچ آزمونی به `Desktop/A` یا `Desktop/B` نمی‌نویسد.

در اجرای عادی، پوشهٔ خروجی پیش از مرحلهٔ ذخیره پاک می‌شود؛ اگر ذخیره بعداً شکست بخورد، محتوای قبلیِ پاک‌شده به‌طور خودکار بازیابی نمی‌شود. کنترل مسیر، استفاده از ریشهٔ درایو، پوشهٔ ورودی، والد ورودی یا مسیرهای پیوندیِ ناامن را رد می‌کند.
